# kulagin-mobile

Мобильное приложение «Сообщество инвесторов» — перенос лендинга
[kulagin-landing](https://github.com/Tribe-I/kulagin-landing) на React Native (Expo).
Два экрана: «Главная» с содержанием лендинга и «О приложении». Все тексты и имена вымышленные.

## Обещания

Часть обещаний исходного лендинга — про HTML-страницу в браузере (`<title>`, теги `H1`/`H2`,
`meta viewport`). В native-приложении (iOS/Android, запуск через Expo Go) этого не существует —
нет DOM. Ниже — обещания, адаптированные под мобильное приложение.

1. Имя приложения в `app.json` — «Сообщество инвесторов» (аналог `<title>`, видно в списке Expo Go).
   На экране «Главная» есть крупный заголовок (аналог H1).
2. На экране «Главная» есть четыре заголовка разделов с `accessibilityRole="header"` (аналог H2):
   «Саммари по рынку», «Топ-5 тем для обсуждения», «Актуальные идеи», «Самые зарабатывающие авторы».
3. В «Топ-5 тем» ровно 5 тем, у каждой число постов видно целиком на любой ширине телефона,
   по каждой теме можно нажать — открывается `https://tribe-i.ru/kulagin/landing/#/topics/<код>`.
4. Приложение читается на телефоне без горизонтальной прокрутки и обрезки текста.
5. В подвале экрана «Главная» есть «Алексей Кулагин».

## Как запустить локально

Нужен Node.js и npm. Из корня репозитория:

```bash
npm install
npx expo start
```

Появится QR-код в терминале.

## Как открыть в Expo Go

1. Установите приложение **Expo Go** на телефон (App Store / Google Play).
2. Запустите `npx expo start` на компьютере (телефон и компьютер — в одной Wi-Fi сети).
3. Отсканируйте QR-код из терминала камерой телефона (iOS) или прямо в Expo Go (Android).

## Хеш коммита на экране «О приложении»

Экран «О приложении» показывает хеш коммита из переменной окружения `EXPO_PUBLIC_COMMIT`.
Если переменная не задана, показывается `dev`:

```bash
EXPO_PUBLIC_COMMIT=$(git rev-parse --short HEAD) npx expo start
```

## Облачная сборка Android (EAS)

APK собирается на серверах Expo (EAS Build), а не локально.

1. Вкладка **Actions** в GitHub → workflow **Android build** → **Run workflow** (ветка `main`).
2. Дождаться зелёного запуска — зелёный означает, что APK собран и готов.
3. Ссылка на страницу сборки и короткий хеш коммита, с которого собрали APK, — в журнале
   запуска (шаг «Publish build link») и в Summary запуска. На странице сборки в Expo есть
   кнопка скачать APK.

Авторизация в Expo — через токен `EXPO_TOKEN`, он лежит только в Secrets репозитория
(Settings → Secrets and variables → Actions) и никогда не печатается в логи.

Хеш коммита, с которого шла сборка, workflow сам кладёт в `EXPO_PUBLIC_COMMIT` на стороне
EAS перед запуском сборки — экран «О приложении» в собранном APK показывает именно его,
а не `dev`.

## Структура

- `App.tsx` — переключение между экранами «Главная» и «О приложении» (без библиотек навигации).
- `src/screens/` — экраны `HomeScreen.tsx`, `AboutScreen.tsx`.
- `src/components/` — `Heading.tsx`, `TopicRow.tsx`, `AuthorRow.tsx`.
- `src/data/landing.ts` — тексты и числа лендинга.
- `eas.json` — профиль `preview` для облачной сборки Android.
- `.github/workflows/android-build.yml` — workflow сборки APK (запускается только вручную).
- `AGENTS.md` — правила работы с репозиторием.

## Как предложить изменение

1. Создайте ветку от свежего `main`.
2. Внесите правки, проверьте `npx expo start`.
3. Откройте Pull Request в `main` и опишите, что изменилось.

Напрямую в `main` не коммитим. Секреты, токены и персональные данные в репозиторий не кладём.
